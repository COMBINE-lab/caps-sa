<section class="capssa-section">
  <h2>What it does.</h2>
  <div class="capssa-feats">
    <div class="capssa-feat">
      <div class="n">01</div>
      <div>
        <h3>Generic over symbols</h3>
        <p>Sort <code>u8</code>, <code>u16</code>, <code>u32</code>, <code>u64</code>, <code>{'[u8; N]'}</code> — anything implementing <code>Symbol</code>. Index width is <code>u32</code>, <code>u64</code>, or <code>usize</code>.</p>
      </div>
    </div>
    <div class="capssa-feat">
      <div class="n">02</div>
      <div>
        <h3>In-memory & external-memory</h3>
        <p>A parallel merge-sort and an in-memory sample-sort for RAM-rich hosts; a disk-spilling sample-sort when the SA can't fit. Same SA, same kernel.</p>
      </div>
    </div>
    <div class="capssa-feat">
      <div class="n">03</div>
      <div>
        <h3>LCP-enhanced merge</h3>
        <p>Carried LCP arrays decide most merge comparisons in <code>O(1)</code>, with a SIMD LCP fast path (AVX-512BW → AVX2 → NEON → scalar) selected once per build.</p>
      </div>
    </div>
    <div class="capssa-feat">
      <div class="n">04</div>
      <div>
        <h3>Streaming output</h3>
        <p>The external-memory path emits SA positions in lex order through a caller closure. Peak RAM stays bounded at <code>{'~O(text + n/p)'}</code> — the SA is never fully materialised.</p>
      </div>
    </div>
    <div class="capssa-feat">
      <div class="n">05</div>
      <div>
        <h3>Sort a subset</h3>
        <p>The <code>*_for_positions</code> entry points sort only the positions you hand them. Filtered positions (N's, spacers) never enter the sort.</p>
      </div>
    </div>
    <div class="capssa-feat">
      <div class="n">06</div>
      <div>
        <h3>Generalized-SA ready</h3>
        <p>A <code>SegmentedText</code> limit-provider stops LCP scans at segment boundaries — the hook STAR-style genome+junction indexes build on.</p>
      </div>
    </div>
    <div class="capssa-feat">
      <div class="n">07</div>
      <div>
        <h3>Optional long-LCP reuse</h3>
        <p>Bounded, partition-local geometric memoization reuses exact long matching intervals without taxing ordinary short comparisons. It remains opt-in and improved the complete ruSTAR-shaped build by 8.4% in isolation.</p>
      </div>
    </div>
  </div>
</section>
